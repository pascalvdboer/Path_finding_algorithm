# P05 proof-workflow: wat er gedaan is (18-11-2026)

Getest met: `php -l` op elk gewijzigd/nieuw PHP-bestand (0 fouten), `npm run build` (exit 0), `php tests/proof/run-proof-php.php`
(**225/225**, ook via `tests/proof/proof-php.test.js` in `npm test`), PHPCS `WordPress.Security.*` op alle P05-bestanden: **0 meldingen**,
e2e op een eigen WP 6.x + WC-site (`BPS_WP_DIR=<scratchpad>/wp-p05 BPS_WP_PORT=8935`): **05 (36/36), 09 (22/22), 18 (36/36)** groen, geen PHP-notices van de plugin.

## Voor andere pakketten
- **P03:** `tests/privacy/run-privacy-php.php` faalt nu op 2 verwachtingen die uitgingen van een ontbrekende Proof_Service: "proefgeschiedenis (zolang Proof_Service er niet is)" bij bewaarde ontwerpen en het aantal exportpagina's (770 → +proefitems per order). Gedrag is correct: proeven zitten nu per orderregel en komen via `export_for_order`. Graag die test aanpassen. Eraser `bps-proofs` is van P05.
- **P06:** `Designs::update_proof()` mag weg (wordt niet meer aangeroepen); `_bps_proof` op de ontwerppost is alleen nog legacy-bron voor de migratie. Core-test meldt `bps_draft_storage_bytes` en `bps_account_rewrite` niet in owned_data (niet van P05).
- **P07:** `Lang::plain()` en de trait `Proof\Fr_Email_Fields` kunnen naar `Emails\Base` verhuizen; mijn code delegeert al naar `Base::plain()` als die bestaat.
- **P08:** instellingen gelezen met fallback: `proof.reminderDays` (3), `fonts[].machineFont` (privé), optioneel `techniques.{id}.proofRequired`, `promises.payAfterProof/cancelUntilProof`.
- **P10:** vul `$fiche['production']['status']` via `bps_fiche_data` (ids `new, proof, approved, digitized, in_production, produced/ready, done/packed/shipped`); bulkprint `Order_Production::render_print( [[order,item],…] )`; "wacht > 7 dagen": orderflag `_bps_proof_open` + `Proof_Service::get( $item )['sent_at']`.
- **P11:** ±60 nieuwe msgids (proefpagina, hele-bestelling-pagina, mails, Mijn account) hebben nog geen FR in de .po; bestaande proef-msgids zijn behouden zodat hun vertaling blijft werken.
- **P01:** header `X-BPS-Design-Token` op `GET /designs/{id}` (security-5, zie handoff).
- **P12:** PHPCS volledige WordPress-standaard op P05-bestanden: enkel nog `CloserSameLine` (sectiebanners), `Capabilities.Unknown` (edit_shop_orders) en uitlijningswaarschuwingen.
