## Contract C5 (voor de andere pakketten)
- `Woo\Config::woo_unit_price( float $excl, ?WC_Product $p ): float` en `Woo\Config::base_tax_rate( string $class ): float`.
- `Woo\Cart::add_design( array $design, array $rights, array $extra = [] )`: `$extra['reorder_of']` = {design_id, order_id, ref},
  `$extra['locked_unit_excl']` (float; alleen server-side, P07 atelier-modus: vaste prijs, engine-checks overgeslagen).
- `Woo\Order::write_line_meta( WC_Order_Item_Product $item, array $bps, ?float $unit_excl = null )` (P07, woo-compat-11).
  Zonder `$unit_excl`: `locked_unit_excl`, anders de actuele engineprijs. `_bps_unit_excl` is altijd excl. btw.
- `Woo\Order::has_custom_made( $order )` en `Woo\Cart::has_custom_made()` (bps, bps_nt, bps_cs).
- `Woo\Order_Again::reorder_design( int $design_id, int $qty = 0, array $rights = [] )` voor de reorder-route (P06/P01).
- `Lead_Time::estimate( array $config, string $technique, ?DateTimeImmutable $now = null ): ?array` en `estimate_many()`.
- `Woo\Cart::apply_price( WC_Product, float )` (price = regular, sale ''), `Woo\Cart::preview_images( $bps )`.
- Filters: `bps_pricing_live_config` (live config van Pricing, hier: verzendzone), `bps_cart_unit_excl` (eenheidsprijs van een
  patchregel; mag een exception gooien = prijsfout, gebruikt door de test).
- `Product::studio_url()` delegeert naar `Frontend\Studio_Pages::url()` (C8) zodra die bestaat.

## Voor andere pakketten
- **P07 (class-emails.php):** gebruik `Order::has_custom_made( $order )` i.p.v. `Order::has_design()` voor het blok "geen herroepingsrecht" (gdpr-juridisch-4). Zonder patchregel geen proefbelofte in die zin (zie `Cart::custom_made_text( false )`). Offerte → order: `Order::write_line_meta( $item, $bps, $unit_excl )`; vaste atelierprijs: `Cart::add_design( $design, $rights, array( 'locked_unit_excl' => … ) )`.
- **P06:** `Designs::clone()` wordt gebruikt met args `parent_id`, `reorder_of` {design_id, order_id}, `status` ('carted' bij Woo-herbestelling, 'draft' in `reorder_design`) en `from_payload` als het ontwerp of zijn preview weg is. Tot dan draait de terugval. `Designs::preview_url( $id, 'cart' | 'cart2x' )` moet `''` of de PNG geven als er geen variant is. De reorder-route kan `Order_Again::reorder_design()` aanroepen (eigenaar/token eerst controleren).
- **P05 (fiche):** P04 voegt via `bps_fiche_sections` de secties `delivery` en `variant_names` toe en via `bps_fiche_data` `$fiche['promised']` {from,to,text}, `$fiche['variantNames']` {names, csvUrl} en `$fiche['downloads'][]` (+ dezelfde secties in `$fiche['sections']` als die sleutel bestaat). Toon de CSV-link op fiche/werkbon. Ordermeta `bps_reorder` hoort bovenaan de fiche ("bestaand borduurbestand gebruiken").
- **P08:** defaults/LIMITS/velden voor `leadTime.{enabled?, productionDays.<techniek>, proofDays, shippingDays, closures[], holidays}`, `fees.perVariantName` (0) en optioneel `shipping.useWooZone` (true). De statusblok-rijen `bps_vat` en `bps_shipping_zone` komen via `bps_status_checks`. Bij `bps_settings_updated` leegt P04 zijn zone-cache.
- **P01/P06 (routes):** `POST /designs` geeft `bps_variant_invalid` (400) door via `bps_payload_validate`; niets te doen. `/quote` en `/cart` krijgen `estimate` vanzelf (Pricing live).
- **JS-prijsmotor (`assets/src/pricing/index.js`, niet van P04):** zelfde regel voor `variantCount`/`perVariantName` toevoegen (handoff-blok P04 in `premium-ui-needs.md`).
- **P13:** e2e 17 gebruikt `tests/security/e2e-helpers.cjs` (P01) voor token/ontwerp en WP-CLI voor de btw-modi en de herbestelling; geen mu-plugin nodig.

## Bekend / niet gedaan
- Product Add-Ons met een verplichte globale groep: niet live getest (betaalde extensie); de meta en de logging zijn er.
- De zone-lezer kent alleen `flat_rate` en `free_shipping` van WooCommerce zelf; andere verzendplugins ⇒ "niet eenduidig" ⇒ config + waarschuwing.
- Herbestellen van naamstrook- en cross-sell-regels via WooCommerce valt buiten de scope (Woo meldt ze als "niet beschikbaar").
